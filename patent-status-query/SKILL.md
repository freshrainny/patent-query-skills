# 专利法律状态查询

通过 CNGC Browser Use（`mac_computer_use_tool` + `plane="bu"` + `seed_browser_use`）访问国家知识产权局专利审查信息查询系统，按申请号批量查询专利并提取"案件状态"，可进一步更新到表格。

## 为什么必须走浏览器

- 网站使用瑞数（Riversafe）动态防护，curl / requests / web_fetch 直连返回 412，请求参数 `hHp4Kgam` 由防护动态注入，不可复现。
- 网站会强制跳转到统一身份认证登录（`tysf.cponline.cnipa.gov.cn/am`），需要用户登录后才能查询。
- 因此本 Skill 一律使用浏览器，不要尝试绕过防护或伪造请求。

## 核心工作流

### 1. 打开查询网站

```python
import seed_browser_use as bu
bu.navigate("https://cpquery.cponline.cnipa.gov.cn/chinesepatent/index")
bu.wait_for_load(timeout=30)
print(bu.page_info())
```

### 2. 处理登录（必现步骤）

打开后页面通常会跳转到统一身份认证登录页（URL 含 `tysf.cponline.cnipa.gov.cn/am`，观察报告 `blocked=auth`）。此时**下一个工具调用必须是**：

```
interaction_request_action(type="browserControl", display_message="国家知识产权局专利查询系统需要登录，请你在浏览器中完成登录（手机号/证件号码 + 密码或扫码），完成后把控制权交回，我会继续自动查询。")
```

用户交回控制后，重新读取 `bu.page_info()`，确认 URL 已回到 `cpquery.cponline.cnipa.gov.cn/chinesepatent/index` 再继续。页面顶部出现"欢迎您，XXX"即登录成功。

### 3. 页面结构与元素定位

登录后进入"中国专利审查信息查询"页，默认在"案件查询 → 申请方式查询"。已知结构：

- **申请号/专利号输入框**：`input[id^="f_"]` 中的第 1 个（placeholder 形如"例如: 2010101995057"）。注意 `bu.find("例如: ...")` 找不到它（placeholder 不是可见文本），**不要依赖 find 定位输入框**。
- **发明名称输入框**：第 2 个 `input[id^="f_"]`（仅兜底搜索用）。
- **查询按钮**：文本同时包含"查询"和"search"的 `button`。
- **结果容器**：`.table_info` div，文本形如 `申请号/专利号：202610504511X发明名称：...申请人：...案件状态：等待实审提案授权公告日：...`。
- **结果总数**：页面文本中的 `共查询到 N 条结果`。

### 4. 批量查询与提取（推荐纯 JS 驱动）

用 `bu.js` 在页面上下文注入原生 setter + input 事件设置输入框，比 `bu.type` 更可靠（避免焦点/清空问题）。完整可复制的代码见 [references/query-scripts.md](references/query-scripts.md)。

每个查询循环必须做到：
1. **先清空全部搜索字段**（申请号、发明名称、申请人等前 5 个 `input[id^="f_"]`），再设置申请号——残留字段会以 AND 逻辑过滤导致 0 结果。
2. 点击查询按钮，等待 3~4 秒。
3. 从 `.table_info` 提取 `案件状态`、返回的 `申请号/专利号`、`发明名称`、`申请人`。
4. **校验返回申请号与查询申请号一致**（归一化后比对），防止读到上一条残留结果；不一致或未找到则重试一次。
5. 记录结果后暂停约 1 秒再查下一个。

单次 `mac_computer_use_tool` cell 内循环处理 6~8 个申请号（每个约 5~6 秒），`timeout_ms` 设为 150000~180000。

### 5. 申请号归一化

查询/比对前统一归一化：
- 去掉前两位字母前缀（如 `ZL`）：`ZL2026104726903` → `2026104726903`
- 去掉所有非字母数字字符（点、空格等）：`202610437475.X` → `202610437475X`
- 统一大写

网站返回的申请号也是归一化形态，比对用同一函数。

### 5.1 申请号 vs 公开号，多来源先去重

- **申请号**是 13 位数字 + 1 位校验位（如 `2022213054739`）；**公开号/授权公告号**是 `CN` + 数字 + 类型字母（如 `CN217624090U`，末位 A/B/U/S 表类型）。两者无数字对应关系，**不能拿公开号和申请号直接比对**，否则会误判"不重合"。
- 判定同一件专利只能申请号对申请号：**前 13 位一致即同一专利**，末位是校验位。
- 合并 PSS、公司台账、第三方等多来源清单时，先归一化到申请号再用集合去重；按申请人检索的结果已包含共同申请，避免对同一批专利重复查询。

### 6. 查无结果时的兜底：发明名称搜索

按申请号查询返回 `共查询到 0 条结果` 时，**不要直接判定专利不存在**。先怀疑表内申请号有误（实践中出现过末位数字缺失），改用发明名称搜索核实：

1. 清空全部字段。
2. 设置**第 2 个**输入框（发明名称）为表格中的专利名称。
3. 点击查询，读取结果，核对返回的 `发明名称` 与 `申请人` 是否与表格一致。
4. 若命中，记录真实申请号与案件状态，并在交付说明中向用户指出申请号差异（**不要擅自改表格中的申请号**，除非用户明确要求）。

### 7. 更新表格（可选）

查询结果写入 Excel 时用 `scripts/update_excel_status.py`（独立于浏览器，确定性可复用）：

```bash
python3 scripts/update_excel_status.py --file 表格.xlsx --mapping status_map.json [--column 6]
```

脚本自动：备份原文件 → 按"行号→状态"写入 → 回读打印验证。`status_map.json` 形如 `{"2": "等待实审提案", ...}`。若原表"法律状态"列在 F 列则无需 `--column`。

**写表纪律**：动手前先读原表确认表头与申请号所在列，写入前逐行校验申请号与预期一致（防错行）；只改状态列，不动其他列与格式；备份只作回滚快照、不交付。

## 关键陷阱清单

1. **专利号口径混淆/重复查询**：公开号（CN…U）当申请号比对会误判不重合。只能申请号对申请号（前 13 位一致即同一专利），多来源先归一化去重，详见 5.1。
2. **字段残留污染**：只设置申请号而发明名称/申请人字段残留旧值 → 0 结果或错结果。每次查询前必须清空全部输入字段。
3. **读到上一条结果**：查询失败时页面仍显示上一条结果。务必校验返回申请号 == 查询申请号。
4. **申请号有误**：表内申请号可能缺位/错位（如 `202511931703` 实为 `2025119317030`），用名称搜索兜底核实。
5. **不要用 find 找输入框**：按 placeholder 找不到；用 `document.querySelectorAll('input[id^="f_"]')` 按下标取。
6. **查询间隔**：连续高频查询可能触发防护/限流，每条间隔 1 秒以上；若页面出现异常（验证码/滑块/空结果），暂停并重新读取页面状态，必要时让用户接管。
7. **常见案件状态值**（供识别核对）：等待实审提案、进入审查、一通出案待答复、公告封卷、驳回失效、驳回等复审请求、复审程序中、授权等。注意"公告封卷"=已走完授权公告流程。
